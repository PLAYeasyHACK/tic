# Reflexão final

## O que aprendi
Aprendi a diferença entre Git e GitHub na prática — Git cuida do histórico e das branches localmente, e o GitHub adiciona a camada de colaboração com pull requests. Entendi como o fluxo de trabalho com branches (`checkout -b`, commits, push, PR, merge) mantém a `main` estável enquanto cada parte do projeto é desenvolvida separadamente.

## Maior dificuldade
A parte mais difícil foi entender os marcadores de conflito de merge (`<<<<<<<`, `=======`, `>>>>>>>`) na primeira vez que apareceram — não estava claro de cara qual trecho vinha de qual branch. Depois de resolver um conflito de propósito, o processo ficou bem mais claro.

## O que faria diferente
Da próxima vez, planejaria melhor a divisão das branches antes de começar a produzir o conteúdo, pra evitar retrabalho e deixar o histórico de commits mais organizado desde o início.
